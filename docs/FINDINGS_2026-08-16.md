## 1. The measurement-instrument problem (headline)

### 1.1 Definition

```
nu = (observed spread across arms) / (2SE seed floor for that readout)
```

A readout with nu < 2 cannot reliably order arms: the differences it reports are within the range that re-running the *same* arm would produce.

**INFERRED.** A metric on which a no-op change outranks every genuine experimental manipulation is not measuring the manipulation. Any ranking read off THUNDER LP at this sample size is indistinguishable from ranking the seeds.

### 1.4 The calibration defect (why even these floors are optimistic)

**MEASURED.** For clsmean/LP the *mean* seed delta is 0.0132 while the 2SE bar generated from the same comparison is 0.0076 — the mean delta is **1.7× the bar it produces**. This is structural: the construction measures dispersion *about* the mean delta across tasks, so a *consistent* offset (every task shifting the same way) contributes to the mean, not the dispersion, and is not penalised at all.

**This is not merely loose — for clsmean/LP it is invalid.** All five per-task deltas are positive (+0.0221, +0.0114, +0.0095, +0.0212, +0.0019) and a paired t-test rejects zero at **p = 0.025** (t = +3.49, n = 5). The two seeds genuinely and reproducibly disagree. The centred bar prices only the component of seed noise that averages away — which is exactly the component we already suppress by averaging over tasks — while ignoring the rigid offset that propagates into our score one-for-one.

**Use `offset_2se = |mean d| + 2·SD/√n`.** Full table in `docs/thunder_seed_floor.md`:

| pooling | task | mean d | SD d | centred 2SE | **offset 2SE** | t | p |
|---|---|---|---|---|---|---|---|
| cls | knn | +0.0040 | 0.0288 | 0.0257 | **0.0297** | +0.31 | 0.771 |
| cls | linear_probing | +0.0066 | 0.0101 | 0.0090 | **0.0156** | +1.46 | 0.219 |
| clsmean | knn | +0.0079 | 0.0435 | 0.0389 | **0.0468** | +0.41 | 0.706 |
| clsmean | linear_probing | +0.0132 | 0.0085 | 0.0076 | **0.0208** | **+3.49** | **0.025** |

`rms_2se` moves in the right direction but still divides the offset by √n, so it under-charges a rigid shift. Report `paired_p` alongside: where p is small, any verdict that leaned on the centred bar needs re-grading — and clsmean/linear-probe is exactly such a case.

**Open item:** the HEST 0.0075 bar was built with the same centred construction and has **not** been recomputed under `offset_2se`. It should be, and it will likely widen. Every HEST verdict in this document and in `RESULTS.md` — ours *and* Waiv's — is graded against a bar that is a lower bound on noise.

## 5. Infrastructure defects found and fixed

1. **`eval_checkpoints.py --max-wait-s` was a cap on TOTAL follower runtime, not idle time.** `t0` was set once before the loop and never reset on progress. **This truncated arm F's first attempt:** the follower printed `[eval] max wait exceeded` while `step_0000750/` was written at 2026-08-16 08:09:46, leaving it unscored and `ri_curve.json` stopping at [250, 500]. Fixed by resetting `t0` after each successful scoring; `gridcmp3.sbatch` now also passes `WAIV_EVAL_MAX_WAIT_S` defaulting to 20 h.
2. **`encoder.py:744` AttributeError** — `'_PoolOnly' object has no attribute 'infer_pool_head'`. `_PoolOnly` (`tests/test_invariants.py:621-631`) is a duck-typed stub that is **not** a `WaivEncoder` subclass and calls the *unbound* `WaivEncoder._pool`, so a class-level default would never be found in its MRO; only `getattr` at the use site works. Fixed as `getattr(self, "infer_pool_head", False)`. Affects 3 test call sites.
3. **A latent defect, guarded rather than fixed.** With `infer_pool_head=True` **and** `retention_kl_weight > 0`, the retention/KL **student** uses arithmetic mean (`pool_from_parts` → `_pool_parts`) while the **teacher** honours the pool head (`retention_teacher_embed` → `embed` → `_pool`); additionally `frozen_teacher` freezes only `backbone.disable_adapter()`, leaving the pool head **live** and the retention target non-stationary. An explicit `ValueError` at `contrastive.py:1525-1531` now refuses the combination before compute starts, so it cannot silently corrupt a run. **Existing results are NOT retroactively affected** — both split and gem have `retention_kl_weight: 0.0` (verified in their `config.json`).
4. **Cache-key hazard.** `run_hest.py:134` keys on `exp_code` with `pool_head` absent from the key, so a `--pool-head` run reusing an `exp_code` would silently score **stale arithmetic-mean features** — manufacturing a null result out of the cache. This is precisely the artefact that would be misread as "GEM doesn't help."
5. **Arm F attempt 1 died on a self-imposed 10 h wall** (`--time=10:00:00`), TIMEOUT at step 805/1500 with the last usable checkpoint at 750. SLURM does not requeue on TIMEOUT.
6. **Arm F attempt 2 (383342) is starved, not compute-bound.** **MEASURED:** `runs/gridcmp3-f-383342/gpu.csv` shows GPU0 at `0 %, 7243 MiB` while stalled; `logs/slurm-waiv-gridcmp3-f-383342.err` shows 63.39 → 320.71 s/step with tiles/s 160 → 45, frozen at step 980. Node n-2 carries four other users' jobs at load average ~23–29. Root cause: CPU/host-RAM contention against 20 dataloader workers plus `--activation-offload`. It will not reach step 1500; the science is unaffected (§2.4).

## 7. What to do next

1. **Rank on RI. Only RI.** HEST and THUNDER become regression checks — "did this break something big" — never selection criteria.
2. **Do not add arms to blind instruments.** A tenth arm through a readout at nu ≈ 1 produces a number, not information.
3. **Buy resolution, not arms.** The marginal GPU-hour is worth far more spent on seed replicates of *existing* arms (shrinking the error bar) than on new configurations (adding points the bar cannot separate).
4. **Treat the geometry axis as closed.** No further (C, T) sweeps. Carry forward the reference geometry C=2 × 192, which fits all three backbones (§4.3).
5. **Head/pooling: wait for the seed study.** Do not act on the split-vs-gem HEST gap until 384434–384438 resolve the sign-flip in §3.1. Whatever the outcome, pin the code for every replicate (§3.3).
6. **Re-derive and commit the THUNDER seed floors** (§1.2), using a construction that penalises a consistent offset rather than only dispersion about the mean (§1.4).
7. **Harden the caches** by putting the backbone slug and `pool_head` into the cache key (§4.4, §5.4). The current scheme's failure mode is a *silent null result* — the most expensive kind of bug this project can have.
